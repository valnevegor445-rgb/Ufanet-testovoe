# #1 - Анализ документации

## *1. Авторизация по договору - Принимает номер договора и пароль, возвращает токен доступа.*
- URL: /api/v1/auth/login
- Метод: POST
- Заголовки: Content-Type: application/json
- **Тело запроса (JSON):** 

{ <br>"contract_number": "", <br> "password": "1234" <br> } 
- **Успешный ответ (200 OK):** 

{ <br> "access_token": "eyJhbGciOiJIUzI1NiIs...", <br> "token_type": "bearer" <br> }

### Что не так:
*В этом запросе номер договора (contract_number) принимает пустое значение, хотя должно принимать и номер договора и пароль.*

### Как должно быть: 
{ <br>"contract_number": "32094969", <br> "password": "1234" <br> } <br><br>
*Должен использоваться валидный номер договора, чтобы получить токен доступа как задумано, иначе в чем смысл авторизации.*

# #2 - Потерянный HTTP-метод

Для запроса с эндпоинтом **/api/v1/auth/request-call** подойдет метод **POST**, потому что подходит для передачи данных в теле запроса и создаёт звонок на указанный номер.

# #3 - Потерянные заголовки

Content-Type: application/json (Заголовок передачи тела в JSON).

Authorization: Bearer {access_token} (Заголовок проверки на права пользователя для выполнения изменения камеры).

---

# #4 - Анализ ответов

**400 (Bad request)** - невалидный JSON, нарушение синтаксиса.

**401 (Unauthorized)** - неверный токен авторизации или его отсутствие.

**403 (Forbidden)** - недостаточно прав, в примере с обновлением камеры.

**404 (Not found)** - объект не найден, тот же пример с камерой, где мы вбиваем её id.

**422 (Unprocessable Entity)** - данные прошли валидацию, но логика неверная.

**429 (Too Many Requests)** - превышен лимит запросов на звонок.

**500 (Internal Server Error)** - Ошибка на сервере.

*Если всё таки в 3 запросе метод DELETE, то:*

**204 (No Content)** - Тело успешно удалено.
